# Работа рядом — Telegram Mini App для поиска работы

Telegram Mini App на **React** с бэкендом на **Node.js + Express + SQLite**.
Авторизация — автоматическая через Telegram `initData` (без формы регистрации):
при первом входе пользователь создаётся в базе по `telegram_id`, при повторном —
просто авторизуется. После входа предлагается выбрать роль: **работодатель** или
**соискатель**.

## Возможности

- 🔐 **Авто-авторизация** через Telegram initData (проверка подписи HMAC-SHA256 ключом бота).
- 👤 **Выбор роли** один раз — на этом регистрация завершена.
- 🧭 **4 вкладки**: Главная · Поиск · Разместить (у работодателя) / Чаты (у соискателя) · Профиль.
- 📝 **Размещение вакансии** работодателем: название, город, зарплата, тип работы, описание (+ требования, график, адрес, категория).
- 🔎 **Поиск с фильтрами**: город, зарплата, тип работы, категория, удалёнка, без опыта, текстовый поиск.
- 🧾 **Карточка вакансии**: «Продавец · 800 $ · Ташкент · Полный день · Опубликовано N ч назад», внутри — описание, требования, график, адрес, компания, кнопки **Откликнуться** / **Написать работодателю**.
- 👔 **Профиль работодателя**: компания, число вакансий, дата регистрации, закрытые вакансии, рейтинг.
- 🙋 **Профиль соискателя**: имя, возраст, город, желаемая зарплата, кратко о себе + редактирование.
- 💬 **Встроенный чат** между соискателем и работодателем по конкретной вакансии.

## Структура

```
server/   — Express API + SQLite (better-sqlite3)
web/      — React + Vite (использует официальный telegram-web-app.js SDK)
```

## Быстрый старт (разработка)

```bash
# 1. Backend
cd server
cp .env.example .env        # укажите BOT_TOKEN (см. ниже)
npm install
npm run dev                 # http://localhost:3001

# 2. Frontend (в другом терминале)
cd web
npm install
npm run dev                 # http://localhost:5173  (api проксируется на :3001)
```

В браузере без Telegram приложение работает в **dev-режиме**: бэкенд выдаёт
тестового пользователя (`ALLOW_DEV_AUTH=1`). Чтобы проверить разные аккаунты —
добавьте `?dev=НОМЕР` к адресу (например `localhost:5173/?dev=5001` — работодатель,
`?dev=6002` — соискатель).

## Деплой за 1 клик (Render, бесплатно, HTTPS из коробки)

В репозитории есть `render.yaml` — готовый blueprint:

1. Запушьте репозиторий в GitHub (уже сделано).
2. Зайдите на [render.com](https://render.com) → **New → Blueprint** → выберите этот репозиторий.
3. Когда Render попросит — вставьте **BOT_TOKEN**. Больше ничего вводить не нужно.
4. Render соберёт фронтенд, запустит сервер и выдаст HTTPS-адрес вида
   `https://rabota-ryadom.onrender.com`.

**Бот настроится сам.** При старте сервер (см. `server/src/bot.js`):
- определяет публичный URL из `RENDER_EXTERNAL_URL`,
- выставляет кнопку-меню бота на Mini App (`setChatMenuButton`),
- отвечает на `/start` кнопкой «🚀 Открыть приложение».

То есть после деплоя достаточно открыть бота в Telegram и нажать кнопку — заходить
в @BotFather вручную не нужно.

> ℹ️ На бесплатном плане Render файловая система временная — база SQLite сбросится
> при перезапуске сервиса. Для постоянного хранения подключите Render Disk
> (`DB_PATH=/var/data/app.db`) или внешнюю БД.

## Деплой через Docker (Railway, Fly.io, VPS)

```bash
docker build -t rabota-ryadom .
docker run -p 3001:3001 -e BOT_TOKEN=ВАШ_ТОКЕН -e PUBLIC_URL=https://ваш-домен rabota-ryadom
```

## Прод-сборка вручную (один процесс)

```bash
npm run install:all
npm run build                               # собирает web/dist
NODE_ENV=production ALLOW_DEV_AUTH=0 BOT_TOKEN=ВАШ_ТОКЕН PUBLIC_URL=https://ваш-домен npm start
```

Сервер сам раздаёт собранный фронтенд из `web/dist` и API на одном порту.

## Подключение к Telegram (если не используете авто-настройку)

1. Создайте бота у [@BotFather](https://t.me/BotFather) → получите **токен**.
2. Задеплойте приложение на HTTPS-домен (Mini Apps работают только по HTTPS).
3. В @BotFather: `/setmenubutton` → укажите URL приложения (или дайте боту настроиться самому).

> ⚠️ Токен бота в исходный код **не коммитится** — он живёт только в переменной
> окружения / `server/.env` (файл в `.gitignore`). Если токен попал в чат или
> репозиторий — отзовите его через `/revoke` у @BotFather и выпустите новый.

## API (вкратце)

| Метод | Путь | Назначение |
|------|------|-----------|
| POST | `/api/auth` | авторизация / авто-регистрация по initData |
| POST | `/api/role` | выбор роли |
| GET/PUT | `/api/me`, `/api/profile` | профиль |
| GET/POST | `/api/vacancies` | список (с фильтрами) / создание |
| GET | `/api/vacancies/:id` | карточка вакансии |
| POST | `/api/vacancies/:id/apply` | отклик |
| GET/POST | `/api/chats`, `/api/messages` | встроенный чат |

Все запросы (кроме `/api/health`) требуют заголовок
`Authorization: tma <initDataRaw>` (в проде) или `Authorization: dev <id>` (в dev).
